## net-sim 에서 물려받은 것 (자세한 사연은 `../net-sim/docs/LESSONS.md`)

### 설계
- 큰 UI 를 만들기 전에 디자인 방향과 상호작용 모델을 먼저 보여 주고 확인받는다. 첫 버전이 "내가 바란 게 아니다" 를 받았다.
- 설정이 바뀌면 그 설정에서 파생된 상태를 무효화한다(쿠버네티스라면: 템플릿이 바뀌면 새 ReplicaSet, Service 셀렉터가 바뀌면 엔드포인트 재계산).
- 모델 → 코어 diff 동기화는 **처리 순서가 곧 의미**다(지우기 전에 알릴 것을 먼저).
- 시계가 조용할 때 멈추는 구조에서는 끝나지 않는 주기 타이머를 일반 타이머로 넣으면 시계가 영원히 뛴다 → 배경 타이머. 주기 동작이 상대에게 일으키는 일반 타이머 사슬의 길이도 따진다(4s).
- 동기 콜백·재진입이 끼는 곳은 **상태 갱신·등록을 먼저, 송신·통지는 마지막에**(세 번 어김 — 4h·4k).
- 기다리는 상태에는 반드시 끝(timeout)을, 서로를 가리킬 수 있는 구성에는 홉·횟수 상한을 둔다.
- 링크·오브젝트 변화를 하나씩 받아 바로 결정하면 "같은 순간의 다른 변화" 를 못 본다 → 0ms 뒤에 모아서 결정(4v).
- 파생 상태를 매번 처음부터 다시 계산하면 새 항목 하나가 기존 배정을 흔든다 → 기존 배정을 먼저 지키고 남는 것만 새로(4v).
- 실제 프로토콜·시스템이 이미 답을 가진 문제는 그 답을 구현한다. 표준의 "왜" 를 빼고 옮기면 그 이유가 버그로 돌아온다(4i).
- 옆에 있는 비슷한 기능의 리뷰 결함 목록을 새 기능을 만들기 전에 체크리스트로 대조한다(4u).
- 설정 변경 = 재시작이 기본이면 켜기만 해도 장애가 난다. "무엇이 바뀌었나" 별로 다르게 처리한다(4r).

### 도구 (Preact + Vite + Playwright)
- Preact signals: `effect` 안에서 `sig.value += 1` 은 Cycle detected → `sig.value = sig.peek() + 1`.
- 전역 CSS 클래스는 컴포넌트 접두어를 붙인다(`.empty`·`.summary` 충돌로 화면이 두 번 깨졌다). 새 클래스 이름은 grep 으로 먼저 확인.
- Playwright: SVG 텍스트는 `textContent()`, Preact 입력값은 프로퍼티라 `evaluateAll(e => e.value)`, `text=문구` 대신 `button:has-text()`, 섹션은 제목(`h3`)으로, 장치는 이름 칸이 정확히 같은 것으로 찾는다. 토스트가 사라질 때까지 기다린다. 움직이는 대상을 누르는 단계는 가끔 놓친다(다시 돌려 보고, 되풀이되면 고친다).
- 검증 스크립트는 Vite 를 별도 포트(5199)로 직접 띄운다. 사용자 프로세스는 건드리지 않는다.
- Bash 도구는 제어 문자가 든 명령을 거부한다 → 긴 파일은 파일 쓰기 도구로.
- 성능은 개발 서버가 아니라 프로덕션 빌드로 잰다. 체감 버벅임은 fps 보다 움직임의 연속성(이름표 튐)부터 의심한다.

### 테스트·검증
- 시나리오는 `runToIdle()` 로 안정화한 뒤, 트레이스는 동작 전 길이를 기록하고 `slice(before)` 로 단언한다. 요약문이 아니라 `kind` 시퀀스로 단언한다.
- 분산·반복 동작은 **종료성**을 따로 검증한다(여러 모양에서 `runToIdle` 이 한도 안에 끝나는지).
- 큰 기능 뒤 깨끗한 문맥의 리뷰 에이전트에게 재현 테스트로 결함을 찾게 하면 매번 실제 결함이 나왔다(한 번에 7~20건). 손실·중복·늦게 온 메시지·"한쪽만 초기화"·같은 순간의 여러 변화를 꼭 시험하게 한다.
- 예제·화면을 바꾸면 스크린샷을 직접 본다. 테스트가 다 통과해도 겹침·잘림은 화면에서만 보인다.
- 리뷰 worktree 는 결과를 옮긴 뒤 지운다. `git add -A` 금지(worktree 가 gitlink 로 담긴다).
